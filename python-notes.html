MODULE 01

Introduction to Python

Python is a high-level, general-purpose programming language known for simple, readable syntax. Used in web dev, data science, automation, AI, and DevOps scripting — often the most beginner-friendly first language.

# Your very first Python program
print("Hello Python")
# Output: Hello Python

What is Python & Why Learn It

  • Interpreted: code runs line by line, no separate compile step — you see results instantly.
  • Why popular: English-like syntax means beginners write working programs in their first hour.
  • Where it's used: Instagram's backend, NASA data analysis, AI models, Ansible automation.
  • DevOps connection: boto3 (AWS SDK), Ansible itself, and most CI/CD glue scripts are Python.
MODULE 02

Installing Python & Setup

Most Linux systems already have Python. This module covers exact commands to check, install, and verify your setup on Linux, Windows, and Mac.

# Check if Python is already installed
python3 --version
# Output: Python 3.11.4

Install Steps by OS

  • Linux (Ubuntu/Debian): usually pre-installed; if not, sudo apt install python3
  • Windows: python.org/downloads → tick "Add Python to PATH" (most common mistake: forgetting this).
  • Mac: pre-installed, but get the latest via brew install python3
  • Run a file: save as hello.py, run with python3 hello.py
MODULE 03

Python Syntax Basics

Python's most unique rule: indentation defines code blocks instead of curly braces. Get the spacing wrong and your program fails to run.

# Comments start with #
if True:
    print("Indented = inside the if block")
print("Not indented = outside the block")

Indentation & Syntax Rules

  • Indentation is mandatory: 4 spaces, never tabs — mixing both causes errors.
  • No semicolons: statements end at the newline.
  • Case-sensitive: Name and name are different variables.
  • Common error: IndentationError: expected an indented block — you forgot to indent after :
MODULE 04

Variables & Data Types

A variable is a named container for data. Python auto-detects the type — "dynamic typing", unlike Java or C.

name = "Devriston"   # str
age = 25             # int
price = 99.50        # float
is_active = True     # bool
print(name, age, price, is_active)

Data Types Explained

  • str: text, wrapped in quotes — single or double, same result.
  • int / float: whole numbers vs decimal numbers.
  • bool: only True or False (capitalised).
  • Convert types: int("25"), str(25), float("9.5")
MODULE 05

Input and Output

print() displays output. input() pauses and waits for typed input — always returned as text, even numbers.

name = input("Enter your name: ")
age = int(input("Enter your age: "))
print(f"Hello {name}, you are {age} years old")

Formatting Output Properly

  • input() is always a string: wrap with int() before doing math.
  • f-strings: f"Hello {name}" — cleanest way to insert variables.
  • Common bug: forgetting the conversion causes TypeError: can't add str and int
MODULE 06

Python Operators

Operators perform math, comparisons (True/False), and logical combinations — used in nearly every line of real code.

x = 10
y = 3
print(x + y)   # 13 — addition
print(x % y)   # 1 — remainder
print(x > y)   # True — comparison

All Operator Types

  • Arithmetic: + - * / // % **
  • Comparison: == != > < >= <= always return True/False.
  • Logical: and, or, not
  • Common confusion: = assigns, == compares — #1 beginner bug.
MODULE 07

Conditional Statements

Conditionals let your program make decisions — the foundation of all program logic.

age = 20
if age >= 18:
    print("Adult")
elif age >= 13:
    print("Teenager")
else:
    print("Child")

if / elif / else Explained

  • if: runs only if condition is True, always ends with :
  • elif: checked only if previous was False — chain as many as needed.
  • Real use case: "if server is down, restart it" — same logic DevOps scripts use.
MODULE 08

Loops in Python

Loops repeat code automatically. for = known repeats, while = repeats until a condition becomes False.

for i in range(5):
    print("Count:", i)
# Prints Count: 0 through Count: 4

For, While & Control

  • range(5): generates 0–4 — stops BEFORE 5, a common beginner trap.
  • break: exits the loop completely. continue: skips to next repeat.
  • Infinite loop warning: always make sure the while condition changes inside the loop.
MODULE 09

Functions in Python

A function is a reusable block of code. Write once, call whenever needed — keeps programs organized and easy to fix.

def greet(name):
    print(f"Hello, {name}!")

greet("Kamran")
# Output: Hello, Kamran!

Parameters & Return Values

  • def: defines a function — it only runs when called by name.
  • return: sends a value back; without it a function returns None
  • Default parameters: def greet(name="Guest") lets you call with no argument.
MODULE 10

Python Collections

Collections store multiple values. Four built-in types — list, tuple, dictionary, set — each with different rules.

fruits = ["apple", "banana", "mango"]
print(fruits[0])   # apple
fruits.append("grape")
print(fruits)

List vs Tuple vs Dict vs Set

  • List [ ]: ordered, changeable — most commonly used.
  • Tuple ( ): ordered, unchangeable — fixed data like coordinates.
  • Dict {key: value}: instant lookup by key, e.g. {"name":"Ali","age":20}
  • Set { }: unordered, auto-removes duplicates.

MODULE 11

Error Handling — try / except

Scripts that crash on the first bad input are useless in production. try/except lets your script handle failures gracefully instead of dying.

try:
    value = int(input("Enter a number: "))
    print(100 / value)
except ZeroDivisionError:
    print("Can't divide by zero")
except ValueError:
    print("That wasn't a number")
finally:
    print("Done checking input")

Why This Matters for Automation

  • try: code that might fail goes here.
  • except: catches a specific error type — be specific, don't use a bare except:
  • finally: always runs — close files, release locks, log "attempt finished".
  • Real use case: a server-check script shouldn't crash just because one host is unreachable.
MODULE 12

File Handling & Paths

Reading configs, writing logs, parsing output files — almost every automation script touches the filesystem.

# Writing and reading a file
with open("status.log", "a") as f:
    f.write("Service checked: OK\n")

with open("status.log", "r") as f:
    for line in f:
        print(line.strip())

Working With Files Safely

  • with open(...) as f: auto-closes the file even if an error happens — always prefer this.
  • Modes: "r" read, "w" overwrite, "a" append.
  • pathlib: modern way to handle paths — from pathlib import Path works across Linux/Windows.
MODULE 13

Modules, pip & Virtual Environments

Real projects use external libraries. pip installs them; venv keeps each project's dependencies isolated so they don't conflict.

# Create and activate a virtual environment
python3 -m venv venv
source venv/bin/activate

# Install and freeze dependencies
pip install requests
pip freeze > requirements.txt
pip install -r requirements.txt

Why Isolation Matters

  • venv: a private copy of Python + packages per project — no version conflicts between projects.
  • requirements.txt: lets anyone (or any CI pipeline) recreate your exact environment.
  • import: use import os for built-ins, no install needed for the standard library.
MODULE 14

Working with JSON & APIs

APIs (AWS, GitHub, monitoring tools) speak JSON. This is how Python scripts talk to them and to your own config files.

import requests, json

response = requests.get("https://api.github.com/users/octocat")
data = response.json()
print(data["login"], data["public_repos"])

# Reading a local JSON config
with open("config.json") as f:
    config = json.load(f)
print(config["server_name"])

JSON Essentials

  • requests: the standard library for calling HTTP APIs — install with pip install requests
  • .json(): converts an API response straight into a Python dictionary.
  • json.load() / json.dump(): read and write JSON files for configs or saved state.
MODULE 15

os & subprocess — Automating Linux

This is where Python actually becomes a DevOps tool: reading environment variables, listing files, and running real shell commands from a script.

import os, subprocess

# Read an environment variable
api_key = os.environ.get("API_KEY", "not set")

# Run a shell command and capture output
result = subprocess.run(
    ["df", "-h", "/"], capture_output=True, text=True
)
print(result.stdout)

Scripting the System

  • os.environ: read env vars/secrets — never hardcode API keys in the script.
  • os.listdir() / os.path: walk directories, check if files/paths exist.
  • subprocess.run(): the safe modern way to call shell commands — capture exit codes, stdout, stderr.
  • sys.argv: read command-line arguments so your script can be reused with different inputs.
MODULE 16

Final Project — Server Health-Check Script

Put it all together: a script that checks disk space and memory, logs the result to a file, and exits with an alert if a threshold is crossed — a real, runnable DevOps tool.

#!/usr/bin/env python3
import subprocess, datetime

def get_disk_usage():
    result = subprocess.run(["df", "-h", "/"], capture_output=True, text=True)
    return result.stdout.splitlines()[1]

def log_status(line):
    with open("/var/log/health_check.log", "a") as f:
        f.write(f"{datetime.datetime.now()} — {line}\n")

try:
    status = get_disk_usage()
    log_status(status)
    usage_percent = int(status.split()[4].replace("%", ""))
    if usage_percent > 85:
        print(f"⚠️  ALERT: Disk usage at {usage_percent}%")
    else:
        print(f"✅ Disk OK: {usage_percent}% used")
except Exception as e:
    log_status(f"ERROR: {e}")
    print("Health check failed — see log")

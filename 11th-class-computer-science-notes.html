Chapter 1Introduction to Software DevelopmentOpen notes

Software development process, SDLC, planning, design, testing and tools

Short Notes

1.1 Software development

Software development is the systematic process of creating computer programs and applications to solve users’ problems. It includes understanding needs, planning, designing, coding, testing, deploying and maintaining software. Good software should meet requirements and be reliable, usable and maintainable.

1.2 Software Development Life Cycle (SDLC)

SDLC is a framework that organizes the work needed to build software from the first idea through deployment and maintenance. It helps teams deliver software that meets user expectations within planned time and cost.

  1. Requirement gathering and analysis: talk to users and stakeholders; identify what the system must do and its quality needs.
  2. Planning: define scope, tasks, schedule, people, estimated cost, resources and risks.
  3. Design: plan the system structure, user interface, data and components before coding.
  4. Implementation / coding: translate the design into source code.
  5. Testing and quality assurance: check whether the software behaves as expected and find defects.
  6. Deployment: make the tested product available to users.
  7. Maintenance: fix problems, improve features and adapt to changing needs.

These stages are often presented in an order, but a team may revisit earlier stages when feedback or a defect reveals a need for change.

1.3 Requirements and project planning

  • Functional requirements describe the functions or services the system must provide, such as allowing a student to log in.
  • Non-functional requirements describe quality attributes or constraints, such as performance, security, reliability and usability.
  • Scope defines what is included in the project and what is outside it.
  • Schedule and milestones divide work into tasks with target dates.
  • Cost estimation considers scope, effort, people, tools and operational needs.
  • Risk management identifies possible problems, estimates their impact and plans ways to reduce them.

1.5 Design, UML and design patterns

Software design describes how a system will be organized before or during implementation. The Unified Modeling Language (UML) provides standard diagrams for describing software systems. A use case diagram shows actors and the functions they use; a class diagram shows classes, their attributes, methods and relationships. Diagrams communicate a plan; they do not replace code or testing.

A design pattern is a reusable solution to a commonly occurring design problem. It is a general approach, not a complete program to copy without considering context.

1.6 Quality assurance, testing and debugging

  • Quality assurance (QA) is the planned work used to help ensure that software meets required standards.
  • Testing runs or checks software to find defects and verify expected behaviour.
  • Debugging is the process of locating, understanding and correcting the cause of a defect.
  • Test normal inputs, boundary values and invalid inputs where appropriate.
  • After fixing a defect, test again to check the correction and to detect unintended side effects.

1.7 Development tools

  • IDE (Integrated Development Environment): combines tools such as a code editor, run/debug controls and project navigation.
  • Compiler: translates source code into another form, commonly machine code or an intermediate form, before execution.
  • Source code repository: stores and tracks code versions so changes can be reviewed and recovered.
  • Framework: a reusable structure, conventions and components that support application development. For example, a web framework may provide routing and templates.

Chapter Summary in Easy Words

Software development turns a user’s need into a working software product. The SDLC gives the team an organized path: understand requirements, plan, design, code, test, deploy and maintain. Planning helps control time, cost, scope and risks. Waterfall moves through planned phases, while Agile works in short cycles and uses feedback. UML diagrams help people understand a system before coding. Design patterns offer reusable approaches to common design problems. Testing checks behaviour; debugging finds and fixes the cause of errors. IDEs, compilers and repositories help developers write, run and manage code.

  • Requirements should be clear before major implementation begins.
  • Functional means “what”; non-functional means “quality or constraint.”
  • UML communicates design; it does not replace implementation.
  • Test after changes, including regression checks.

  • Do not assume that all projects must follow Waterfall; methodology depends on project needs.
  • A design pattern is a reusable design approach, not a complete ready-made application.

Chapter 2Python ProgrammingOpen notes

Python basics, variables, operators, control flow, functions, data structures and files

Short Notes

2.1 Programming and Python

Computer programming means writing instructions that a computer can execute. Python is a high-level, general-purpose language known for readable syntax. It is used in web development, data analysis, automation and artificial intelligence.

2.2 Writing and running Python

Python code can be written in a code editor or an Integrated Development Environment (IDE), then run with a Python interpreter. A .py file stores a Python program. Use meaningful file names and save the file before running it.

print("Hello, world!")

Output:

Hello, world!

2.3 Variables and data types

A variable is a name that refers to a value. Python uses dynamic typing, so the type is associated with the value at runtime.

name = "Ayesha"   # str: text
age = 16          # int: whole number
marks = 87.5      # float: decimal number
is_present = True # bool: True or False
print(name, age, marks, is_present)

Common built-in types include int, float, str, bool, and collection types such as list. Identifiers may use letters, digits and underscores, but cannot begin with a digit or contain spaces. Python is case-sensitive: total and Total are different names.

2.4 Input, output and conversion

name = input("Enter your name: ")
age = int(input("Enter your age: "))
print("Hello", name)
print("Next year you will be", age + 1)

input() returns text. Convert it with functions such as int() or float() when numeric calculation is needed. print() displays values.

2.6 Decision-making and loops

marks = 72
if marks >= 80:
    print("Excellent")

    print("Passed")

Python uses indentation to define a block. A for loop iterates over a sequence or iterable; a while loop repeats while its condition is true. Use break to leave a loop and continue to skip to its next iteration.

for number in range(1, 4):
    print(number)

Output: 1, 2, 3 on separate lines. The stop value in range(1, 4) is excluded.

2.7 Functions, modules and lists

def add(a, b):
    return a + b

result = add(4, 3)
print(result)

Output: 7. A function is a reusable block of code. Parameters receive input values; return sends a result back to the caller. A module is a file or package of reusable Python code that can be imported.

subjects = ["English", "Computer", "Math"]
print(subjects[0])
subjects.append("Physics")
print(len(subjects))

List items are ordered and accessed by index. Python indexing begins at 0. Lists can be changed after creation.

2.8 Object-oriented programming, exceptions and files

Object-oriented programming (OOP) organizes code around classes and objects. A class defines a kind of object; an object is an instance of a class. Attributes store data and methods define behaviour.

try:
    number = int(input("Enter a whole number: "))
    print(10 / number)
except ValueError:
    print("Please enter a valid whole number.")
except ZeroDivisionError:
    print("The number must not be zero.")

Exception handling lets a program respond to certain runtime errors instead of stopping unexpectedly. File handling can use with open(...) so the file is closed automatically:

with open("notes.txt", "w", encoding="utf-8") as file:
    file.write("Study Python")

with open("notes.txt", "r", encoding="utf-8") as file:
    content = file.read()
    print(content)

Output: Study Python. Use "r" to read, "w" to write (replacing existing content), and "a" to append. Test with valid, invalid and boundary inputs, and use debugging to locate mistakes.

Indentation matters in Python. Functions let you reuse code, modules let you import code, and lists store ordered collections. OOP uses classes and objects. try/except handles selected errors. Files can be read or written using open(), preferably inside a with block. Run small examples, read error messages and test different inputs.

Chapter 3Algorithms and Problem SolvingOpen notes

Computational problems, algorithm design, searching, sorting and complexity

Short Notes

3.1 Computational problems

A computational problem is a problem that can be described and solved through a computational process. It has an input (given data), a process (the rules or algorithm) and an output (the result). A clear problem statement identifies what is given and what result is required.

3.2 Algorithms

An algorithm is a finite, ordered set of clear steps for solving a problem. A good algorithm should be unambiguous, produce the intended result, finish after a finite number of steps and use resources sensibly. Algorithms can be represented using plain language, pseudocode or flowcharts.

3.3 Generate-and-test

The generate-and-test method creates a possible solution and checks whether it meets the conditions. If it fails, another candidate is generated and tested. It is simple, but may be inefficient when there are many candidates.

3.4 Solvability and complexity

A problem is solvable if an algorithm can produce a correct answer for the problem as defined. An unsolvable problem has no algorithm that can solve every valid instance under the stated model. Complexity describes the resources needed as input size grows, often time or memory.

  • P: decision problems solvable in polynomial time by a deterministic algorithm.
  • NP: decision problems for which a proposed solution can be verified in polynomial time.
  • NP-hard: at least as hard as every problem in NP under the relevant reductions; an NP-hard problem need not itself be in NP.
  • NP-complete: problems that are both in NP and NP-hard.

These categories describe theoretical difficulty. They do not mean that every NP problem is known to be impossible to solve.

3.5 Algorithm design techniques

  • Divide and conquer: divide a problem into smaller subproblems, solve them and combine the results. Binary search is a classic example of repeatedly reducing the search interval.
  • Greedy method: choose what seems best at each step. It is correct for problems where local choices lead to a global optimum under the problem’s conditions.
  • Dynamic programming: solve and store results of overlapping subproblems so the same work is not repeated.

3.6 Searching algorithms

Linear search checks items one by one. It works on unsorted or sorted data, but may inspect every item. Binary search compares the target with the middle item and discards half the remaining range each step. Binary search requires the data to be sorted.

def binary_search(items, target):
    low, high = 0, len(items) - 1
    while low <= high:
        mid = (low + high) // 2
        if items[mid] == target:
            return mid
        elif items[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

print(binary_search([2, 4, 6, 8, 10], 8))

Output: 3 (the index of 8). A return value of -1 means the target was not found in this example implementation.

3.7 Sorting algorithms

Bubble sort repeatedly compares adjacent items and swaps them when they are in the wrong order. After each pass, a large item moves toward the end. It is easy to understand but inefficient for large lists.

def bubble_sort(items):
    items = items.copy()
    for end in range(len(items) - 1, 0, -1):
        for i in range(end):
            if items[i] > items[i + 1]:
                items[i], items[i + 1] = items[i + 1], items[i]
    return items

print(bubble_sort([5, 2, 4, 1]))

Output: [1, 2, 4, 5]. The copy prevents the original list from being changed by this function.

3.8 Graph traversal: BFS and DFS

A graph contains vertices (nodes) connected by edges. Breadth-first search (BFS) explores nearby vertices level by level and commonly uses a queue. Depth-first search (DFS) follows a path as far as possible before backtracking and commonly uses a stack or recursion. Both need a way to track visited vertices to avoid repeatedly processing cycles.

Complexity asks how time or memory grows with input size. P, NP, NP-hard and NP-complete are theoretical complexity categories. Divide and conquer breaks a problem into smaller pieces; greedy algorithms choose locally attractive options; dynamic programming saves results of repeated subproblems. Linear search checks items one at a time. Binary search is faster on sorted data by discarding half the range. Bubble sort repeatedly swaps adjacent items. BFS explores a graph level by level using a queue; DFS explores deeply and backtracks.

Important Short Questions with Answers

What are input, process and output?

Input is the given data, process is the algorithm’s steps, and output is the result.

The algorithm decides which half to discard based on order; that decision is not reliable on unsorted data.

What is the generate-and-test method?

Generate a candidate solution, test it against the conditions and repeat until a suitable solution is found or candidates are exhausted.

BFS explores level by level, usually using a queue; DFS explores deeply before backtracking, often using a stack or recursion.

What does complexity measure?

It describes how resource needs, such as time or memory, grow with input size.

Key Points to Remember

  • Write down the required input and output before choosing an algorithm.
  • Binary search requires sorted data.
  • BFS commonly uses a queue; DFS commonly uses a stack or recursion.
  • An algorithm should be clear, finite and correct.
  • Complexity considers how resource use grows as the input grows.

Quick Revision

Common Mistakes

  • Do not say NP means “not possible”; it concerns verification in polynomial time.
  • Do not confuse NP-hard with NP-complete: NP-complete problems are also in NP.

Chapter 4Computational StructuresOpen notes

Lists, stacks, queues, trees and graphs

Short Notes

4.1 What is a computational structure?

A data structure organizes data so it can be stored, accessed and updated effectively. Choosing a suitable structure depends on the operations needed, the relationship between data items and performance requirements.

4.2 Lists

A list stores elements in sequence. In Python, lists use square brackets and items are separated by commas. Indexing begins at zero.

numbers = [10, 20, 30]
numbers.append(40)   # insert at the end
numbers[1] = 25      # update index 1
print(numbers)
print(numbers[0])

Output: [10, 25, 30, 40] then 10. Common operations include access, traversal, insertion, deletion, searching and updating.

4.3 Stacks: LIFO

A stack follows Last-In, First-Out (LIFO): the last item added is the first removed. The main operations are push (add an item), pop (remove the top item) and peek/top (inspect the top item). Examples include undo operations and the call stack used by programs.

stack = []
stack.append("A")  # push
stack.append("B")
print(stack.pop()) # pop: B

4.4 Queues: FIFO

A queue follows First-In, First-Out (FIFO): the first item added is the first removed. Enqueue adds an item at the rear; dequeue removes an item from the front. Queues model waiting lines and task scheduling. In Python, collections.deque is useful for efficient operations at both ends.

from collections import deque
queue = deque(["A", "B"])
queue.append("C")       # enqueue
print(queue.popleft())  # dequeue: A

4.5 Trees

A tree is a hierarchical structure made of nodes connected by edges. The root is the top node; a parent has child nodes; a leaf has no children. A binary tree allows each node to have at most two children. Trees can represent folders, organization charts and hierarchical data.

4.6 Graphs

A graph contains vertices (nodes) and edges (connections). Graphs may be directed or undirected and may have weighted edges. They can model road networks, social connections and communication networks. A path is a sequence of connected vertices. A cycle is a path that returns to a previously visited vertex according to the graph’s rules.

4.7 Traversal, searching and selection

Traversal means visiting the elements or nodes of a structure. Lists are traversed in sequence; trees and graphs require a traversal strategy such as BFS or DFS. Searching looks for a required value or node. Select a structure based on how the data will be used:

StackLIFOUndo history, nested function calls

Chapter Summary in Easy Words

Data structures organize data for effective use. A list stores items in a sequence and allows access by index. A stack removes the most recently added item first (LIFO), while a queue removes the earliest added item first (FIFO). Trees represent hierarchy using parent and child nodes. Graphs represent relationships using vertices and edges. Traversal visits items or nodes; searching looks for a value. Choose a structure according to the problem: lists for sequences, stacks for last-added-first, queues for first-added-first, trees for hierarchy and graphs for networks.

Key Points to Remember

  • LIFO means last in, first out; FIFO means first in, first out.
  • Python list indexing starts at zero.
  • Stacks use push/pop; queues use enqueue/dequeue.
  • Trees model hierarchy; graphs model general relationships.
  • Choose structures based on required operations and performance.

  • A graph is not always a tree; graphs can contain cycles and multiple routes.

Chapter 5Data AnalyticsOpen notes

Statistics, model building, experiments and data visualization

Short Notes

5.1 Data analytics and statistics

Data analytics is the process of examining data to discover useful information, patterns and trends that support decisions. Statistics provides methods to summarize and interpret data. Data should be checked for missing, incorrect or inconsistent values before drawing conclusions.

5.2 Measures of central tendency

  • Mean: add all values and divide by the number of values.
  • Median: arrange values in order and find the middle. With an even number of values, average the two middle values.
  • Mode: the value or values that occur most frequently.

Example: for 50, 60, 70, 80, 90, mean = (50 + 60 + 70 + 80 + 90) ÷ 5 = 70; median = 70; there is no single mode because every value occurs once.

5.3 Spread and descriptive statistics

Measures of central tendency describe a typical value, but not how spread out the data is. The range is maximum minus minimum. Variance and standard deviation describe variation around the mean; a larger standard deviation usually indicates more spread. Descriptive statistics summarize observed data rather than automatically explaining why a pattern occurred.

5.4 Model building and evaluation

A model is a simplified representation used to describe data or make estimates. A typical workflow is: define the question, collect relevant data, clean it, explore patterns, select a suitable method, build the model, evaluate its performance and communicate results. Use data that is relevant to the question and consider whether it represents the population being studied.

  • Separate training and testing data when evaluating a predictive model, where appropriate.
  • Do not judge a model only on the same data used to build it.
  • Check whether errors are acceptable for the real-world task.
  • Explain limitations and uncertainty rather than presenting an estimate as guaranteed truth.

5.5 Experimental design

Experimental design plans how to collect evidence to answer a question. Define the question, variables, method, sample and measurements. Keep conditions consistent where possible. A control group or comparison condition can help identify the effect of a treatment. Random assignment can reduce certain kinds of bias. Correlation between two variables does not by itself prove that one causes the other.

Data analytics examines data to support decisions. Statistics helps summarize it. The mean is the arithmetic average, the median is the middle value after sorting, and the mode is the most frequent value. Range and standard deviation describe spread. Visualizations make patterns easier to understand: bars compare categories, lines show trends, histograms show distributions and scatter plots show relationships. A chart must be labelled clearly, and correlation alone does not prove cause and effect.

Mean uses all values in a calculation; median is the middle value after arranging data in order.

A bar chart is usually suitable.

To check how well it performs on data not used to build it.

What should a good chart include?

A clear title, labelled axes, units where needed and an appropriate scale.

  • Mean, median and mode describe central tendency in different ways.
  • Use a chart suited to the question and data type.
  • Evaluate models honestly and communicate their limitations.
  • Correlation is not proof of causation.

Quick Revision

Check and clean data before analysis. Mean, median and mode describe central tendency; range and standard deviation describe spread. Select a suitable chart, evaluate models carefully, and do not confuse correlation with causation.

Common Mistakes

  • Do not calculate the median before ordering the values.
  • Do not use a line chart for unordered categories without a meaningful sequence.
  • Do not claim that a relationship proves cause and effect.

Chapter 6Emerging TechnologiesOpen notes

Cloud computing, virtualization, service models, blockchain and future trends

Short Notes

6.1 Emerging technologies

Emerging technologies are developing or increasingly adopted technologies that can change how people, organizations and systems work. This chapter focuses on cloud computing and blockchain, their uses, and issues related to security and resources.

6.2 Cloud computing

Cloud computing provides computing resources such as servers, storage, networks, platforms or applications over a network, often with on-demand access. Users can obtain resources when needed without buying and managing every physical component themselves.

  • On-demand access: resources can be provisioned when required.
  • Scalability: capacity can be increased or reduced to match workload.
  • Resource pooling: a provider shares underlying resources among customers while separating their workloads.
  • Measured service: usage may be monitored for billing or capacity planning.
  • Virtualization: software abstracts physical computing resources so multiple virtual environments can share hardware.

6.3 Cloud service models

ModelProvider commonly managesCustomer commonly manages
IaaS — Infrastructure as a ServicePhysical servers, storage, networking and virtualization layerOperating system, installed software, applications and data
PaaS — Platform as a ServiceInfrastructure plus operating system/runtime and managed platformApplication code and its data/configuration
SaaS — Software as a ServiceThe complete application and underlying platform/infrastructureUsing the application, user settings and permitted data management

The exact division of responsibility depends on the provider and service. A useful memory aid: IaaS gives infrastructure, PaaS gives a development platform, and SaaS gives ready-to-use software.

6.4 Cloud deployment models

  • Public cloud: services offered to customers over shared provider infrastructure.
  • Private cloud: cloud environment dedicated to one organization.
  • Hybrid cloud: connected use of private and public cloud environments.
  • Multi-cloud: use of services from more than one cloud provider. It is not the same as hybrid cloud, though an organization may use both.

Cloud decisions should consider security, privacy, compliance, availability, cost, vendor dependence, network connectivity and backup/recovery plans.

6.5 Blockchain technology

Blockchain is a distributed ledger in which records are grouped into blocks linked using cryptographic techniques. Copies may be maintained by multiple participants in a peer-to-peer network. Consensus rules help participants agree on the accepted state of the ledger. Design choices vary, so not every blockchain is fully public or completely immutable in every circumstance.

  • Distributed ledger: a record shared across multiple participating systems.
  • Peer-to-peer (P2P) network: participants communicate directly as peers rather than relying on one central server for every operation.
  • Cryptographic hash: a fixed-length value calculated from data; changing the data changes the hash with very high probability.
  • Smart contract: code deployed on a blockchain that executes according to defined conditions and platform rules.

Applications can include cryptocurrency transactions, tracking products through a supply chain and executing certain digital agreements. Blockchain can improve shared record integrity in suitable settings, but does not automatically guarantee that input data is true, private or legally valid.

6.6 Future directions and responsible use

Edge computing processes data near the device or place where it is produced, which can reduce delay and network traffic for some tasks. Cloud and edge systems can complement one another. Evaluate emerging technology by its real use case, cost, security, energy/resource needs, privacy and maintainability rather than assuming that newer always means better.

Chapter Summary in Easy Words

Cloud computing lets people use computing resources over a network when they need them. Virtualization helps share physical hardware. Scalability means resources can grow or shrink with demand. IaaS provides infrastructure, PaaS provides a platform for building and running applications, and SaaS provides ready-to-use software. Public, private, hybrid and multi-cloud describe different deployment arrangements. Blockchain is a distributed ledger shared by participants, often using cryptographic links and consensus rules. It can support transactions, smart contracts and supply-chain tracking, but does not make all data automatically correct or private. Edge computing processes data closer to where it is created.

Important Short Questions with Answers

Differentiate IaaS, PaaS and SaaS.

IaaS offers infrastructure, PaaS offers a managed platform for applications, and SaaS offers a ready-to-use application.

What is virtualization?

It uses software to create virtual computing resources or environments on physical hardware.

Differentiate hybrid cloud and multi-cloud.

Hybrid combines private and public cloud environments; multi-cloud uses more than one cloud provider.

What is a blockchain?

A distributed ledger with records linked in blocks using cryptographic techniques and shared validation rules.

What is a smart contract?

Code deployed on a blockchain that runs when its programmed conditions and platform rules are met.

What is edge computing useful for?

It can process data close to its source to reduce delay or network traffic in suitable applications.

These are revision questions based on chapter concepts, not guaranteed examination questions.

Key Points to Remember

  • IaaS = infrastructure; PaaS = platform; SaaS = software.
  • Virtualization abstracts physical resources.
  • Hybrid cloud and multi-cloud describe different arrangements.
  • Blockchain is a distributed ledger, not a guarantee that all stored information is true.
  • Evaluate security, privacy, cost, availability and resource use before adopting a technology.

Quick Revision

Cloud services provide computing resources on demand. IaaS offers infrastructure, PaaS a platform, and SaaS ready-to-use software. Understand deployment models, virtualization and blockchain, and assess privacy, security, cost and limitations.

Common Mistakes

  • Do not assume a cloud customer has no security responsibilities.
  • Do not confuse hybrid cloud with multi-cloud.
  • Do not claim blockchain guarantees the truth of data entered into it.

Chapter 7Legal and Ethical Aspects of Computing SystemOpen notes

Terms of use, privacy, security threats, digital divide, bias and digital citizenship

Short Notes

7.1 Terms of use and responsible access

Terms of Use, also called Terms and Conditions or Terms of Service, are rules that explain how a website, app or service may be used and what rights and responsibilities users and providers have. Read relevant terms before accepting them. Follow applicable laws, licences and institutional policies.

7.2 Privacy and data protection

Privacy concerns a person’s ability to control information about themselves. Personal data may include names, contact details, identifiers, location or other information that can identify a person. Responsible data handling means collecting only what is needed, explaining its purpose, limiting access, protecting it and keeping it only as long as justified.

  • Use strong, unique passwords and multi-factor authentication where available.
  • Keep operating systems and applications updated.
  • Check permissions and privacy settings.
  • Do not share another person’s private information without a proper basis or permission.
  • Use backups and access controls to reduce the impact of data loss or unauthorized access.

7.3 Security threats and prevention

ThreatMeaningRisk reduction
PhishingMessages or pages that trick people into revealing information or taking unsafe actions.Verify the sender and destination; do not rush to open unexpected links or attachments.
MalwareSoftware designed to harm, spy on, disrupt or gain unauthorized access to systems.Install trusted software, update systems and use appropriate security tools.
Weak/reused passwordsCredentials that are easy to guess or compromised across multiple accounts.Use long, unique passwords and a password manager where appropriate.
Unauthorized accessAccess to a device, account or data without permission.Use least privilege, access controls, MFA and careful account management.
Data lossInformation becomes unavailable or is destroyed.Keep tested backups and a recovery plan.

7.4 Intellectual property

Intellectual property (IP) refers to creations of the mind that may receive legal protection. Copyright commonly protects original expression such as written work, software code, images and music. Trademarks distinguish goods or services by signs such as names or logos. Patents may protect qualifying inventions under applicable law. Exact rights, exceptions and procedures depend on the relevant jurisdiction.

Credit sources, respect licence conditions, do not present another person’s work as your own, and check whether you have permission to reuse material.

7.5 Digital divide and bias

The digital divide is the gap between people or communities in access to digital devices, reliable connectivity, skills or useful digital services. It can be affected by income, location, disability, language and education. Accessible design, digital skills training and affordable connectivity can help reduce the gap.

Bias in computing systems occurs when data, design choices or system behaviour unfairly disadvantages people or groups. For example, a model trained on unrepresentative data may perform poorly for people missing from that data. Use representative data where possible, test outcomes across groups, document limitations and provide ways to report problems.

7.6 Ethics and digital citizenship

Ethics concerns principles for deciding what is fair, responsible and harmful. Legal compliance and ethical conduct overlap but are not identical: an action may be legal yet still be unfair or disrespectful. Digital citizenship means participating online safely, respectfully and responsibly.

  • Communicate respectfully and avoid harassment.
  • Check information before sharing it; correct errors when discovered.
  • Respect privacy, consent, copyright and access permissions.
  • Consider the effects of technology on people and society.
  • Report serious abuse or security issues through appropriate channels.

Chapter Summary in Easy Words

Computing creates legal and ethical responsibilities. Terms of use explain the rules for using a service. Privacy means respecting personal information, and data protection includes limiting collection, controlling access and securing information. Phishing, malware, weak passwords and unauthorized access are common risks; updates, careful link checking, strong unique passwords, MFA and backups help reduce them. Intellectual property includes protected creative works, trademarks and qualifying inventions. The digital divide is unequal access to devices, connectivity and skills. Bias can occur when data or design unfairly affects groups. Digital citizenship means acting safely, respectfully and responsibly online.

Important Short Questions with Answers

What is the purpose of Terms of Use?

They explain permitted use and the rights and responsibilities of users and providers.

Name three ways to improve online security.

Use unique passwords, enable MFA and keep software updated. Verify links and maintain backups as well.

Differentiate copyright and trademark.

Copyright generally protects original expression; a trademark distinguishes the source of goods or services.

What is the digital divide?

Unequal access to devices, internet connectivity, digital services or the skills needed to use them.

How can bias enter a computing system?

Through unrepresentative data, assumptions in design or decisions about how the system is built and evaluated.

What is digital citizenship?

Using digital tools safely, respectfully and responsibly while considering others’ rights.

Key Points to Remember

  • Protect personal information and only collect what is needed.
  • Verify unexpected messages and links.
  • Respect licences, copyright and other intellectual property rights.
  • Digital access includes connectivity and skills, not just device ownership.
  • Test computing systems for unfair outcomes and document limitations.

Quick Revision

Use digital systems lawfully and ethically. Protect personal information, verify suspicious messages, update software and keep backups. Respect intellectual property, consider digital inequality, and test systems for unfair bias.

Common Mistakes

  • Do not assume that everything found online is free to copy.
  • Do not share passwords or one-time authentication codes.
  • Do not treat legal compliance as the only measure of ethical behaviour.

Chapter 8Online Research and Digital LiteracyOpen notes

Research questions, source evaluation, advanced search, ethics and intellectual property

Short Notes

8.1 Online research and digital literacy

Online research is the process of finding and evaluating information on the internet to answer a question or investigate a topic. Digital literacy is the ability to use digital tools effectively, find and judge information, create content and act safely and responsibly online.

8.2 Plan a research task

  1. Define a focused question and identify what evidence would answer it.
  2. Choose useful search terms, synonyms and alternative phrases.
  3. Search more than one suitable source; do not rely only on the first result.
  4. Evaluate the source and compare claims against independent evidence.
  5. Record useful facts and complete source details while researching.
  6. Organize findings, write in your own words and cite the sources used.
  7. Review the final work for accuracy, relevance, fairness and clear presentation.

8.3 Evaluate online sources

Check authority (who created it and their expertise), accuracy (evidence and corroboration), currency (when it was published or updated), purpose (to inform, sell, persuade or entertain), and relevance to your question. A polished design or high search ranking does not guarantee that a source is reliable.

8.4 Advanced search techniques

Search syntax differs across services. Use the search engine’s help when a command does not behave as expected.

8.5 Digital libraries and research databases

Digital libraries and databases organize electronic books, articles, reports and other resources. Search by title, author, subject, keywords or publication date. Use filters to narrow results and save full citation details. Check whether a source is a primary source, a review or a summary, and confirm access and reuse conditions.

8.6 Research ethics and intellectual property

Research ethics includes honesty, accurate reporting, respect for privacy, responsible handling of evidence and proper acknowledgement of other people’s work. Plagiarism is presenting another person’s words or ideas as your own without appropriate acknowledgement. Paraphrasing means explaining an idea in your own words, but the source should still be cited when the idea comes from someone else.

Intellectual property includes rights such as copyright and trademarks. Do not assume an online image, video, code sample or article can be reused without restrictions. Check the licence, ask permission where necessary and follow attribution requirements.

8.7 Digital safety and content creation

  • Use privacy settings and limit public sharing of personal details.
  • Check downloads and links; use trusted sources.
  • Use accessible headings, readable contrast and alternative text when creating digital content.
  • Check facts, spelling, links and citations before publishing.
  • Distinguish evidence from opinion and disclose uncertainty when appropriate.

Chapter Summary in Easy Words

Online research means finding and evaluating internet information to answer a focused question. Digital literacy includes searching, checking sources, creating content and staying safe. Plan the research before searching. Evaluate authority, accuracy, currency, purpose and relevance. Search operators and filters can narrow results, but syntax varies by service. Digital libraries help locate organized resources. Keep source details while working, compare evidence and cite what you use. Plagiarism presents another person’s work as your own; paraphrasing still requires acknowledgement when the idea came from a source. Respect privacy, copyright and licences when creating or sharing content.

Authority, accuracy, currency, purpose and relevance.

AND narrows to results containing both concepts; OR broadens the search to either term where supported.

So the researcher can verify information and create accurate citations later.

Chapter 9Entrepreneurship in Digital AgeOpen notes

Innovation, design thinking, business planning, market research, pitching and finance

Short Notes

9.1 Entrepreneurship and innovation

Entrepreneurship is the process of identifying an opportunity, organizing resources and creating value through a product, service or venture. Entrepreneurs face uncertainty and make decisions about customers, costs, delivery and growth. Innovation means applying a new or improved idea in a useful way; it does not have to be a completely new invention.

9.2 Design thinking

Design thinking is a human-centred approach to solving problems by understanding people’s needs, exploring ideas and improving solutions through feedback. A common cycle is:

  1. Empathize: understand the people who experience the problem.
  2. Define: state the specific problem to solve.
  3. Ideate: generate and compare possible solutions.
  4. Prototype: make a simple version of an idea.
  5. Test: ask users to try it, learn from feedback and improve it.

The process is iterative. Testing may reveal that the team needs to redefine the problem or create a different prototype.

9.3 Market research and customer value

Market research gathers information about customer needs, demand, alternatives and competitors. It can use surveys, interviews, observation, public data and small product tests. Questions should be clear and should not pressure people toward a preferred answer.

  • Target market: the customer group the business intends to serve.
  • Customer problem: the need or difficulty the offering addresses.
  • Value proposition: a clear statement of the benefit offered and why a customer might choose it.
  • Competitor analysis: examines alternatives, strengths, weaknesses and market gaps.

Evidence from potential customers is more useful than assuming that everyone will want the product.

9.4 Business plan

A business plan explains how a venture will create and deliver value and remain financially workable. Depending on the business, it may include:

  • Executive summary and business idea.
  • Customer problem, target market and value proposition.
  • Product or service description and competitive advantage.
  • Marketing, pricing, sales and distribution strategy.
  • Operations, resources, suppliers and team responsibilities.
  • Financial estimates, budget, cash-flow forecast and funding needs.
  • Risks, assumptions, milestones and measures of progress.

9.5 Business pitch and storytelling

A business pitch is a concise presentation intended to explain an opportunity and persuade a particular audience to take a next step. A clear pitch identifies the problem, proposed solution, target customers, evidence of demand, business model, competition, team and request (for example, feedback, a partnership or funding). Use realistic evidence, simple visuals and a clear structure. Storytelling can make the customer problem and intended impact easier to understand, but should not replace facts.

9.6 Marketing, sales and communication

Marketing helps the right audience learn about and understand an offering. A marketing strategy considers the target market, positioning, product, price, place/distribution and promotion. A sales strategy describes how the business will reach prospects, explain value, handle questions and convert interest into purchases. Track results and improve based on evidence.

9.7 Financial basics

  • Revenue: money earned from sales or services before subtracting expenses.
  • Cost/expense: resources consumed or payments made to run the business.
  • Profit: revenue minus costs for the period, using the chosen accounting basis.
  • Budget: a plan for expected income and spending.
  • Cash flow: money moving into and out of the business over time.
  • Financial forecast: an estimate of future financial results based on assumptions.
  • Break-even point: the level where total revenue equals total costs.

Profit and cash flow are related but not identical: a business can show a profit on paper and still struggle to pay bills if cash arrives late. Forecasts are estimates, not guarantees.

9.8 Collaboration and iteration

Teams benefit from clear responsibilities, respectful communication, shared goals and feedback. Iteration means improving an idea or product through repeated cycles of testing and revision. Keep track of what was learned, what changed and why.

Chapter Summary in Easy Words

Entrepreneurship turns an opportunity into value for customers. Innovation improves an idea, product or service. Design thinking begins by understanding people, defining their problem, generating ideas, building a prototype and testing it; feedback may send the team back to an earlier step. Market research checks customer needs and competing options. A business plan describes customers, value, marketing, operations, risks and finances. A pitch explains the problem, solution, evidence and request clearly. Marketing attracts and informs the target audience; sales turns interest into customers. Revenue is income from sales, profit is revenue minus costs, and cash flow tracks money moving in and out. Collaboration and iteration help improve the venture over time.

Important Short Questions with Answers

What are the common stages of design thinking?

Empathize, define, ideate, prototype and test.

Why is market research important?

It provides evidence about customer needs, demand, competitors and possible market gaps.

What is a value proposition?

A clear statement of the value an offering provides and why a customer might choose it.

What should a business plan include?

The idea, target market, value proposition, marketing and sales, operations, financial estimates and risks.

How are profit and cash flow different?

What makes a business pitch effective?

Key Points to Remember

  • Start with a real customer problem and gather evidence.
  • Design thinking is iterative, not always a one-way process.
  • A prototype helps test assumptions before a larger investment.
  • A business plan links market, operations and finances.
  • Revenue is not the same as profit; profit is not the same as cash flow.
  • Customer feedback and collaboration help improve a product.

Quick Revision

Common Mistakes

  • Do not treat a prototype as a finished product.
